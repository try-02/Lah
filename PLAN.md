# PLAN
## Keputusan
- K1: Akses penyimpanan memakai kontrak `RepositoriBerkas` di `commonMain` dengan adapter terpisah Android/iOS — menghindari `expect/actual` berlebihan dan menjaga domain tetap murni (opsi: satu `expect/actual` besar ✗ perawatan tinggi; opsi: lapisan penyimpanan generik di luar stack ✗ tidak ada pustaka KMP netral).
- K2: Diff memakai implementasi Myers berbasis baris sendiri di `commonMain` (opsi: pustaka diff pihak ketiga ✗ kompatibilitas KMP belum terverifikasi; opsi: panggil `git diff` ✗ melanggar batasan eksekusi shell).
- K3: Arsip — baca ZIP memakai `FileSystem.openZip()` dari Okio 3.18.2; tulis ZIP/GZIP memakai adapter internal tipis yang membungkus `java.util.zip` (Android) dan `platform.zlib` (iOS) — disahkan pemilik, tidak menambah pustaka arsip pihak ketiga (fallback lama: pustaka arsip multiplatform ✗ butuh verifikasi lisensi/iOS).
- K4: Pencarian isi memakai pemindai streaming sendiri (Okio + Flow, dapat dibatalkan) — deteksi biner/ukuran dan batas file per hasil dibuat eksplisit (opsi: indeks lokal FTS ✗ masuk P2 dan jauh lebih berat untuk v1).
- K5: Metadata lokal (bookmark, riwayat lokasi, beranda) memakai SQLDelight; preferensi skalar memakai storage preferensi platform — SQLDelight sudah menjadi stack wajib, preferensi cukup untuk satu nilai.
- K6: Simpan aman memakai temp file + verifikasi (ukuran/checksum) sebelum mengganti target, dengan fallback tulis–verifikasi–baca ulang — kegagalan tidak boleh menghilangkan perubahan lokal.
- K7: Perencanaan ini mencakup P0 v1.0 (§3); fitur P1/P2 (syntax highlighting lanjut, mode file besar, 7z, Termux, dsb.) dijadwalkan terpisah — menjaga satu task per sesi tetap kecil.
- K8: Matriks versi terverifikasi disahkan pemilik — iOS 14.0, SQLDelight 2.4.1, Koin 4.2.2, Okio 3.18.2, kotlinx-coroutines 1.11.0, kotlinx-datetime 0.8.0, kotlinx-serialization-json 1.11.0, Android minSdk 30/compileSdk 37/targetSdk 37, target iOS `iosArm64` + `iosSimulatorArm64` — angka berasal dari pemilik, bukan hasil tebakan.
